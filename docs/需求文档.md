> 版本：v1.0（2026-09-18）

## 1. 项目概述

### 1.1 定位

面向中小嵌入式团队的内部构建/测试/发布系统，开源（MIT）。

- 解决的问题：嵌入式产品（如 YY0133）的固件构建、设备刷机部署、自动化测试、生产发布，目前全靠手工 + SecureCRT 脚本，无统一平台
- 部署形态：单台编译服务器（当前 192.168.0.80，root 运行），Web 访问
- 串口设备经 Windows 串口客户端透传接入
- 界面中英文双语，预留其他语言

### 1.2 核心流程

```
构建 → 部署 → 测试 → 发布
```

- **构建**：把源码（git 仓库/本地目录）编译成产物，带完整记录与校验
- **部署**：把产物装到设备上（手动 / SSH / 刷机）
- **测试**：对设备执行测试集合，产出报告
- **发布**：把构建产物拷贝到生产目录

### 1.3 开源与仓库

- 许可证：MIT
- 单仓库：`server/`（Go 后端）+ `serial-client/`（Windows 客户端）+ `web/`（Vue3 前端）
- API 按 OpenAPI 注解，自带 Swagger UI

### 1.4 技术栈

| 层 | 选型 |
|---|---|
| 服务器后端 | Go（单二进制） |
| 数据库 | SQLite |
| 前端 | Vue3 |
| 串口客户端 | Go + Wails（与服务器共享连接协议/日志格式代码） |
| 实时推送 | WebSocket（构建/部署/测试/会话日志统一一条通道，按记录 ID 订阅） |

### 1.5 用户与权限

- 简单登录 + 两级角色：管理员 / 普通成员
- 管理员开账号（用户名 + 初始密码），不做自注册
- 权限：管理员管配置（工程、规则、系统设置），成员执行操作（触发构建、部署、测试、发布、看记录、下载产物）
- 记录级执行人：构建/部署/测试/发布记录均带执行人字段；第一版不做独立配置审计日志
- 服务端 session + cookie，服务器重启后重新登录

### 1.6 组织模型

- **工程（Project）** 是所有配置的顶层容器
- 所有配置（构建项目、部署规则、设备、测试单元/项/集合、发布规则）默认**工程级隔离**
- **配置中心**：工程内统一管理四类规则的页面，tab 分组（构建项目 / 部署规则 / 测试管理 / 发布规则 + 设备）
- 跨工程复制粘贴：四类规则 + 设备均支持
- JSON 导出/导入：**所有规则类型**均支持（开源后跨团队分享配置）
- 系统级设置（管理员页）共四项：
  1. 最大并行批次数（默认 4）
  2. 产物校验方式（默认 sha256，可选 md5）
  3. 发布/备份根目录白名单
  4. 构建临时目录路径

## 2. 构建板块（MVP 第一）

### 2.1 工程与构建项目

- 可自建工程（如 YY0133），工程下配置多个**构建项目**（bootfw、u-boot、rootfs 补丁等）
- 构建项目配置项：
  - 名称
  - 源类型：**git 地址** / **服务器本地目录**（两者都必须是 git 仓库）
  - git 最新源码检查（可选）：配置分支名，可选 commit；勾选后构建前核对分支/commit 并拉取远端最新
  - 构建命令（如 `./bb.sh D2000_YY_301_0070_defconfig && ./bb.sh`）
  - 产物声明：**必须相对构建目录的相对路径**，支持通配（如 `bootfw*.bin`）；仓库外绝对路径不允许
  - 构建超时（可选，不填不限时）
  - 版本提取命令（如 `ver.sh -a`）：构建后执行，完整输出（系统版本、内核版本、补丁版本等）全部记录为该次构建的版本信息
  - 前置项目：可多个、可跨工程引用、**前置分组**（组内 OR、组间 AND）

### 2.2 源与 dirty 检查

- git 地址源：浅克隆，按分支取最新 2 个 commit
- 本地目录源：`git clone` 本地仓库到临时目录（硬链接，快且省空间）
- **dirty 拒建**：两种源类型构建前都检查工作区是否 dirty，dirty 则拒绝构建并提示前端
- 本地干净目录不在原地构建，一律 clone 到临时目录

### 2.3 批次与执行

- **一键构建/部分构建**：工程页全选/部分选中构建项目，触发一个**批次**
- 批次内按前置关系构建；界面须清晰可视化前置关系（组内 OR / 组间 AND，说明文案 + 关系图示）
- 语义细则：
  - 组内 OR：任一前置成功即可；组间 AND：全部组成功才构建本项目
  - 前置失败 → 本项目跳过，标「跳过-前置失败」
  - 批次内同项目只构建一次（多个项目共同前置 A，A 只跑一次）
  - 跨批次不自动复用（每次批次都重新构建前置）
- 全局最多 4 个批次并行（系统设置可改），超出的批次**排队等待**，空位释放自动开始
- 构建命令继承系统运行环境（root），工具链/环境变量由构建命令自行管理
- 仅 Web 手动触发，第一版不做定时构建、API 触发

### 2.4 构建记录

每条构建记录包含：

- 时间
- 源快照（commit）
- 执行日志：克隆、检查、命令输出、结果，分段可查
- 产物清单：路径 + 校验和（校验方式系统级配置，默认 sha256）
- 版本信息（版本提取命令的完整输出）
- 状态：排队/执行中/成功/失败/已取消/跳过-前置失败
- 执行人

界面能力：

- 实时构建任务查看（WebSocket 推送日志）
- 构建历史查询
- 取消（杀进程树，标「已取消」，临时目录清理）
- 删除/全部删除：**提示三选**——仅删记录 / 连带产物 / 取消
- 产物 Web 下载，带校验和显示
- 历史日志 <10MB 全量加载，超限提示「下载查看」

### 2.5 删除与临时目录

- 第一版**纯手动删除**，不做自动保留策略
- 「保留产物删记录」时产物成孤儿（无归属、占盘），直至手动清理
- 临时目录：默认在数据目录下（管理员可配置路径）
  - 构建成功：产物归档后**即删**
  - 构建失败：**保留 7 天**自动清理（后台清理循环）
  - 取消：**即清**

## 3. 部署板块（MVP 第二）

### 3.1 部署规则

部署全部通过**部署规则**管理。规则先选**部署方式**，再按方式出不同配置表单：

### 3.1.1 手动部署

- 部署步骤说明：规则内一份 markdown（含产物引用），部署时界面展示说明 + 产物下载列表，给测试人员看
- 第一版说明静态不跟版本变；需要版本差异化就建多条规则

### 3.1.2 SSH 部署

- 设备 SSH 信息：ip、端口、用户名、密码（凭据加密存储，密钥来自启动配置）
- 命令模板 + 变量注入，配置固定不随产物版本变化。三类变量：
  1. **产物变量**（自动注入）：`${artifact.url}`、`${artifact.name}`、`${artifact.version}` 等
  2. **设备变量**（自动注入）：`${device.ip}` 等
  3. **参数**（部署时人填）：规则里定义参数名和默认值，模板里 `${params.xxx}` 引用
- 部署结果和记录要有反馈

### 3.1.3 刷机部署（expect 步骤序列）

刷机规则 = **一串可配置的 expect 步骤**。参考 SecureCRT VBS 脚本的「等待字符串 + 发送 + 超时」三要素模型：

- 每个步骤：等待字符串 + 可选发送内容 + 超时 + 失败动作
- 覆盖流程：reboot → uboot（等待字符串/密码/延时/命令）→ ramdisk（是否登录、用户名密码、执行命令或脚本）→ 安装 → 验证
- 分发参数全在刷机规则里配置：
  - TFTP 目录、NFS 目录、服务器 IP
  - U 盘盘符、目录
  - 部署哪些文件、部署到哪个目录（单个/多个目录）
  - 分发目标支持本机目录 + 远程 SSH 推送
- U 盘刷机：系统生成**按规则布局好的 zip 包**（目录名对齐实际路径，如 `301-0070/<版本文件夹>/`）+ 操作指引；操作员下载解压拷进 U 盘
- 目标形态通用可配置，适配多种刷机方式（U 盘/TFTP+NFS/recovery 分区等）

### 3.2 设备管理

- 设备挂在工程下登记（工程级隔离）：名称、SSH 信息（ip/端口/用户/密码）、备注
- 串口参数（波特率等）在客户端配置，服务器不存
- 状态指示灯（设备列表页）：
  - **串口在线**：客户端共享时指定所属设备（下拉选），服务器绑定「设备 ↔ 串口在线」
  - **SSH 可达**：不做自动探测，提供「Test」按钮手动点一次探活；测试中出现不通则上报异常

### 3.3 会话

- 会话 = 服务器与设备间一次串口/SSH 交互，全程带时间戳日志
- 分两类：**任务会话**（刷机/测试运行，自动创建）、**手动会话**（随时可开，挂设备下，独立编号独立日志）
- 一台设备同一时间只有一个活跃会话；忙时**拒绝并提示「设备忙」**（不做排队——排队只存在于构建批次）
- 手动会话日志记录**所有串口数据，有输入就记**（收发双向带时间戳，类似 SecureCRT 会话记录）
- 手动会话终端在 **Web 界面**（xterm.js）；客户端不做终端
- 会话日志：
  - 服务端落盘，格式 `2026-09-18 22:31:05.123 RX/TX | content`
  - 第一版手动删
  - Web 展示末尾 N 行（如 1000 行）+ 完整下载（流式）
  - 按设备维度存历史，测试报告引用会话 ID 链接

### 3.4 串口客户端（serial-client）

- 测试人员 Windows 电脑上的 exe，简单 GUI，从服务器 Web 界面下载（版本自动匹配）
- 功能：登录服务器 + 扫描串口 + 打开/关闭/共享串口（选设备 + 配波特率）+ 状态显示 + 收发计数
- **纯透传，无业务逻辑**：COM 口 ↔ TCP 长连接 ↔ 服务器会话层；expect 步骤、PASS/FAIL 判定、日志时间戳、报告全在服务端
- 客户端主动长连接服务器，断线重连
- 技术栈 Go + Wails，与服务器共享连接协议和日志格式代码

### 3.5 断线处理

- 双层检测：服务器↔客户端心跳（秒级感知）+ 客户端上报 COM 口异常（拔线/串口失效）
- 任务中断线 = 任务标记**失败终止**，记录断线时刻，会话日志保留已收部分（尾部标注「连接中断」），操作员重新发起

### 3.6 部署记录与取消

- 部署记录 = 构建记录 + 部署规则 + 设备 + 执行人 + 时间 + 结果 + 会话日志引用
- 部署/测试运行可人工取消：取消 = 关会话 + 标记失败；**刷机取消需二次确认**（提示设备可能处于半刷状态）

## 4. 测试板块（MVP 第三）

### 4.1 三层模型

```
测试用例单元（最小单元）
  └→ 组合成 测试项（step 序列）
       └→ 组合成 测试集合（按系统组合，工程可多套）
```

全部挂工程下，支持跨工程复制粘贴。

### 4.2 测试用例单元

配置项：

- 通路：**自动（默认）/ 串口 / SSH** 三选一，界面每种方式带说明文案（auto = 串口优先，无串口走 SSH）
- 执行内容：shell 脚本或命令（用户友好直接配置）
- 期望字符串 + 匹配方式：**包含（默认）/ 正则 / 精确**
- PASS/FAIL 标准
- FAIL 后动作（可配置）：**暂停 / 取消测试 / 继续**

### 4.3 测试项与 step

- 测试项 = step1、step2… 组合
- step 类型三种：
  1. **自动**：执行测试用例单元
  2. **人为观察**：配置时填**提示词**（如「LED 亮」「蜂鸣器响」），测试人员看/听设备后在 Web 界面确认
  3. **人为干预**：配置时填提示词（如「拔掉一根电源线」），测试人员物理操作后在 Web 界面确认
- 人为节点确认 = PASS/FAIL 按钮 + 可选备注（进报告）+「重试此 step」+「标记 FAIL 继续」
- 示例（电源状态测试项）：step1 人为干预插双电源上电 → step2 人为观察双电源灯亮 → step3 登录系统 → step4 命令查双电源 PASS → step5 人为干预拔一根电源线 → step6 命令查单电源 PASS

### 4.4 测试集合与测试运行

- 测试集合 = 测试项序列，**第一项恒为版本查看**
- 集合内测试项：添加时选 + 上移/下移排序
- **版本查看**：从设备读出版本与期望版本比对；期望版本默认取**该设备最近一次部署**所用构建记录的版本
- 测试运行 = 设备 + 测试集合 + 关联构建记录、部署规则、发布规则（报告自动带版本）
- 串口会话全程共享不断开（整个测试运行期间）

### 4.4 测试报告

- 默认 txt；可导出 word（以 `E:\1_ZJ_Cloud\002.projects\嵌入式产品-测试报告-模板.docx` 为模板基准），默认不输出、有导出功能
- 报告内容：
  - 报告头：工程名、设备名、**构建产物版本**、测试集合、执行人、起止时间
  - 总判定（PASS/FAIL）
  - 测试项/step 明细表（step 名、方式、结果、备注）
  - **测试总结 + 失败项目列表**
  - 会话日志引用（会话 ID 链接）

## 5. 发布板块（MVP 第四）

### 5.1 发布规则

工程级配置对象：

- 目标目录：**可多个**，每项标**本机目录**（直接拷贝）或**远程目录**（SSH 推送，复用 SSH 凭据模型）
- 备份目录：可选，可配置**日期后缀**格式（如 `backup-20260101`）
- 同一构建产物不同版本：先删除后覆盖
- 目标目录受**管理员白名单**约束：系统设置登记允许的根目录，发布规则选根 + 子路径，校验必须落在白名单内（远程目录按 SSH 主机 + 路径登记）——防误删源码等事故

### 5.2 发布动作

- 发布 = 选**发布规则** + 勾选**构建记录**（如 #0012，选中后自动载入产物清单，如 `d2000-0YY-449-0133-kylinsec-generic-*.sh`），发布所勾选构建记录的**全部产物**
- 发布时**弹窗确认**：是否要备份，还是要覆盖
- 产生发布记录（谁、何时、发了什么、到哪、备份/覆盖、结果）

## 6. 非功能与边界

### 6.1 实时性

- WebSocket 统一推送：构建日志、部署日志、测试运行进度、会话日志一条通道，按记录 ID 订阅
- 刷机 expect 实时性要求高，不用轮询

### 6.2 安全

- SSH 密码/刷机密码：**加密存储**（对称密钥，密钥来自启动配置），防数据库文件直接泄露；第一版不做 vault 级方案
- 发布白名单（见 5.1）
- root 运行（内网单机信任环境），架构上不禁止改

### 6.3 界面

- 中英文双语（第一版），前端文案集中管理（i18n 结构），预留其他语言

### 6.4 第一版明确不做

| 项 | 处理 |
|---|---|
| 定时构建 / API 触发 | Web 手动触发即可 |
| 构建记录自动保留策略 | 纯手动删 |
| 通知（邮件/钉钉/webhook） | Web 实时推送已覆盖；webhook 列后续 |
| 设备忙排队 | 拒绝提示（仅构建批次排队） |
| 测试用例管理系统 | 不做用例库管理，只做三层执行模型 |
| 对外分发渠道 | 发布到目录即止 |
| 细粒度权限 | 两级角色够用 |
| 任意布尔依赖表达式 | 前置分组（组内 OR / 组间 AND）够用 |

```
→ 发 "sh /run/media/sda1/301-0070/<folder>/recovery.sh" → 等 "install over"
→ 发 reboot → 等 "localhost login:" → 二次登录
→ 后续命令（ifconfig/mount NFS/跑测试脚本）
```

### 7.3 MVP 交付顺序

1. **构建板块**（需求最成熟、独立性强）
2. **部署板块**（SSH + 手动先行，刷机随后）
3. **测试板块**（依赖串口通路）
4. **发布板块**（最简单，随时可插）

> 注：串口客户端（serial-client）是部署板块刷机方式和测试板块的前置依赖，需在部署板块开发期同步启动。
